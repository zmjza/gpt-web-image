# 嵌套模型菜单修复设计

## 目标

修复 ChatGPT 网页模型菜单升级为嵌套 Radix 子菜单后，`gpt-web-image` 在提交前误认父菜单、点击被输入区遮挡或无法确认模型选择的问题，同时保留“不确定时禁止提交”的安全门禁。

## 已确认故障

- 任务 `task_mt77ag1o_b436ay4j` 把带有 `data-has-submenu`、`aria-haspopup="menu"` 的父菜单项当成目标模型，指针点击被 `thread-bottom-container` 拦截并超时。
- 任务 `task_mt77c460_syq8rb96` 打开了菜单，但旧确认逻辑没有识别新层级中的能力选择器，最终以 `MODEL_SELECTION_UNCERTAIN` 停止。
- 参考图哈希、Chrome、Profile、输出目录和登录状态均正常，失败发生在任何提示词或附件提交之前。
- 现有夹具只有扁平模型菜单和直接能力选择器，没有嵌套子菜单与指针遮挡场景。

## 方案

1. 模型文本分类必须只接受唯一语义。一个节点同时包含高、中、极速时视为容器，不得归类为任一模型。
2. 带 `aria-haspopup="menu"`、`data-has-submenu` 或 `aria-expanded` 的节点属于子菜单入口，不得作为最终模型选项。
3. 模型菜单打开后，如果发现能力子菜单入口，则通过聚焦和键盘打开，随后重新读取其中的 slider/group；避免依赖会被覆盖层拦截的指针点击。
4. 最终模型选项也优先使用键盘激活。确认必须来自该选项的选中属性、能力 slider 的值和对应文本，或原模型触发器的明确状态；不能扫描任意同名按钮作为证据。
5. 结构仍不明确时继续返回 `MODEL_SELECTION_UNCERTAIN`，三种模型均被明确标记不可用时才返回单日限额。

## 测试

- 单元测试证明混合父节点不会被分类成高、中或极速。
- 受控浏览器夹具增加嵌套 Radix 菜单、能力子菜单和遮挡层；修复前稳定失败，修复后选择 `GPT-5.6 Sol 高` 并完成生成。
- 保留扁平菜单、能力选择器、模型回退、额度判断和延迟 hydration 的既有覆盖。
- 完整执行类型检查、全量测试、集成测试、构建、安全审计与 diff 检查。
- 使用用户本轮上传图片运行真实 `edit --reference`，要求模型选择证据、附件证据、稳定会话、唯一媒体卡、原图下载和成功终态全部落盘。
