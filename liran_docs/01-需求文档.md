# GPT 网页生图 Skill 需求文档

> 产品需求总览。所有 P0/P1 功能均已映射到模块与测试；当前均为待开发。

## 用户场景

| 场景 | 用户 | 想达成 | 触发时机 |
|---|---|---|---|
| 自然语言生图 | Codex 用户 | 不记命令即可生成图片 | 明确描述“生成/画/做几张图片” |
| 显式调用 | Codex 用户 | 强制使用 ChatGPT 网页生图 | 输入 `$gpt-web-image` |
| 参考图改图 | Codex 用户 | 上传一张或多张图片并按要求修改 | 提供附件或本地路径 |
| 连续修改 | Codex 用户 | 保留原对话语境继续调整结果 | 指向刚生成的某张图片 |
| 批量生图 | Codex 用户 | 请求 1–10 张并逐张看到结果 | 明确数量或沿用默认数量 |
| 登录恢复 | 账号所有者 | 首次登录或处理验证码后继续任务 | Profile 未登录或被要求验证 |
| 中断恢复 | Codex 用户 | 避免重复提交并继续检查已有任务 | Codex、脚本或浏览器异常退出 |
| 跨平台使用 | 同一用户 | 在 Mac 与 Windows 使用一致流程 | 安装到受支持设备 |

## 业务规则

- 明确请求直接执行；歧义确认前不得创建网页提交。
- 第一次未指定数量时为 1，之后使用上一次明确数量，范围始终限制在 1–10。
- 新任务新建 ChatGPT 对话；连续修改复用原对话。
- 单张结果自动选中；多张且目标不明确时必须询问；仅明确“全部修改”才批量改图。
- 补图只在原会话进行，最多 3 轮；部分成功也要立即交付已有结果。
- 只有下载并校验通过的文件才可触发 `image_ready` 和成功计数。
- 生成成功但下载失败属于独立失败，不得降级为截图交付。

## 非功能需求

- 安全：零凭据落盘、日志脱敏、目录边界校验、不规避平台控制。
- 可靠：幂等提交、防串图、事件序号、原子文件操作、中断恢复。
- 可观测：状态变化产生结构化事件，异常产生脱敏证据。
- 可移植：核心逻辑不依赖 shell 方言、盘符、路径分隔符或 WSL。
- 可测试：页面判断通过可控夹具覆盖，真实 ChatGPT 仅用于受控真机验收。

## 实用性论证

- F01/F09 将原本跨应用的重复手工操作收敛为 Codex 内的一次请求，是产品成立基础。
- F06/F07/F08 防止“网页看似生成但下载错图或文件损坏”，直接决定结果可信度。
- F10 处理长任务常见的中断与不确定性，避免重复消耗 Plus 使用量。
- F15 防止仅在开发机工作却声称跨平台完成。
