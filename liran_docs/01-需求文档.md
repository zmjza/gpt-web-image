# GPT 网页生图 Skill 需求文档

> 产品需求总览。所有 P0/P1 功能均已映射到模块与测试；当前均为待开发。

## 用户场景

| 场景 | 用户 | 想达成 | 触发时机 |
|---|---|---|---|
| 自然语言生图 | Codex 用户 | 不记命令即可生成图片 | 明确描述“生成/画/做几张图片” |
| 显式调用 | Codex 用户 | 强制使用 ChatGPT 网页生图 | 输入 `$gpt-web-image` |
| 图生图 | Codex 用户 | 上传一张或多张本地图片作为参考并生成新图 | 提供附件或本地路径，走 `edit --reference` |
| 图改图 | Codex 用户 | 修改本工具此前从 ChatGPT 网页生成并交付的指定图片 | 指定源任务和结果 ID，走 `refine` |
| 连续修改 | Codex 用户 | 保留原对话语境继续调整结果 | 指向刚生成的某张图片 |
| 批量生图 | Codex 用户 | 请求 1–10 张并逐张看到结果 | 明确数量或沿用默认数量 |
| 登录恢复 | 账号所有者 | 首次登录或处理验证码后继续任务 | Profile 未登录或被要求验证 |
| 中断恢复 | Codex 用户 | 避免重复提交并继续检查已有任务 | Codex、脚本或浏览器异常退出 |
| 跨平台使用 | 同一用户 | 在 Mac 与 Windows 使用一致流程 | 安装到受支持设备 |

## 业务规则

- 明确请求直接执行；歧义确认前不得创建网页提交。
- 第一次未指定数量时为 1，之后使用上一次明确数量，范围始终限制在 1–10。
- 新任务新建 ChatGPT 对话；连续修改复用原对话。
- 单张结果自动选中；多张且目标不明确时必须询问；仅明确“全部修改”才批量改图。
- 补图只在原会话进行，最多 3 轮；部分成功也要立即交付已有结果。
- 只有下载并校验通过的文件才可触发 `image_ready` 和成功计数。
- 生成成功但下载失败属于独立失败，不得降级为截图交付。

## 本轮核心修复合同

- 文生图不接受本地参考图；图生图缺少本地参考图必须失败；图改图不接受本地参考图，必须绑定指定源任务的稳定网页会话。
- 每次网页提交前按 `GPT-5.6 Sol 高`、`GPT-5.6 Sol 中`、`极速` 选择模型。三者均被网页明确标记不可用时返回 `单日生图已达限额，暂时不可生图。`；菜单结构不明确不得误报限额。
- 同一 Profile 的任务可以跨进程并发入队，但网页 Composer 串行提交；结果必须按任务 ID、回合、媒体卡、下载原图和 SHA-256 一一对应。
- 真实 Chrome 在上传、提交、等待、下载、校验、回显和 task.json 落盘完成前保持运行；后台任务只最小化项目专用窗口。

## 非功能需求

- 安全：注册表、task.json、日志和诊断零凭据落盘；完整备份是用户主动创建的未加密认证数据归档，必须本机保存并显示警告；同时执行日志脱敏、目录边界校验和平台控制。
- 可靠：幂等提交、防串图、事件序号、原子文件操作、中断恢复。
- 可观测：状态变化产生结构化事件，异常产生脱敏证据。
- 可移植：核心逻辑不依赖 shell 方言、盘符、路径分隔符或 WSL。
- 可测试：页面判断通过可控夹具覆盖，真实 ChatGPT 仅用于受控真机验收。

## 实用性论证

- F01/F09 将原本跨应用的重复手工操作收敛为 Codex 内的一次请求，是产品成立基础。
- F06/F07/F08 防止“网页看似生成但下载错图或文件损坏”，直接决定结果可信度。
- F10 处理长任务常见的中断与不确定性，避免重复消耗 Plus 使用量。
- F15 防止仅在开发机工作却声称跨平台完成。

## 本轮新增功能：多 Profile 管理系统

### F16 Profile 注册表与自动扫描（P0）

- 维护本机 `profile-registry.json`，记录默认保存根目录、历史保留目录和已登记 Profile 的非敏感元数据。
- macOS 初始根目录为 `~/Library/Application Support/gpt-web-image`，Windows 初始根目录为 `%LOCALAPPDATA%\\gpt-web-image`。
- 现有 `chrome-profile` 原地保留并自动注册；新 Profile 默认位于 `<root>/profiles/<profile-id>`。
- 自动扫描只扫描当前默认根目录的约定层级和有效项目归属标记，不扫描全盘或日常 Chrome。
- 注册表写入必须原子化，路径必须规范化并防越界、符号链接和重复注册。

### F17 Profile CRUD、导入与默认目录（P0）

- HTML 页面支持创建、查询、修改名称/账号备注/说明、导入已有专用 Profile、修改默认根目录和刷新扫描。
- 修改默认根目录时必须显示迁移、保留和取消；迁移处理所有已登记 Profile，先复制、校验再切换并移除源目录；失败保留源数据；保留则旧 Profile 留在历史目录，新 Profile 使用新目录。
- 外部导入路径必须用户主动选择和确认；默认 Chrome 日常 Profile 必须拒绝。

### F18 唯一启用与会员资格（P0）

- 同时只能启用一个 Profile；任务开始时绑定 `profileId` 和规范化路径。
- 启用前检查目录、归属标记、登录状态、会员等级和占用状态。
- 只接受明确识别为 Plus、Pro 或 Go 的会员等级；其他等级或检测技术失败都禁止启用。
- 会员检测使用账户菜单、会员计划页面和可用功能多信号校验，自动重试，不把未知当作可用。

### F19 专用浏览器与生图接入（P0）

- 全局同时只能有一个项目专用 Chrome 进程；用户可以在其他标签页普通浏览，生图任务使用独立标签页。
- 不控制用户日常 Chrome；关闭按钮只能关闭项目启动并记录的进程。
- `generate/edit/refine/resume` 只使用当前启用 Profile，禁止静默回退。

### F20 删除、备份与恢复（P0）

- 页面删除必须二次确认并真实删除指定 Profile 目录；当前启用、占用或任务中的 Profile 不能删除。
- 自动任务、cleanup、升级、恢复和异常处理永远禁止删除 Profile。
- 支持包含 Chrome 登录数据的完整未加密本地备份；备份前必须关闭浏览器并结束任务；恢复默认生成新 Profile。

### F21 本地 HTML 管理页面（P0）

- 本地服务只监听 `127.0.0.1`，不需要网页密码，不开放局域网。
- 页面使用中文，适配 macOS/Windows，覆盖列表、表单、弹框、加载、空态、错误、占用、迁移预检、备份警告和成功/失败反馈。

## 本轮新增边界

- 本轮先完成文档和微观任务，不直接写业务代码或 UI 壳。
- 不提供云端同步、外部数据库、账号系统、密码/Cookie/Token 展示或日常 Chrome 接管。

## 本轮新增功能：图片管理

### F22 图片管理页面（P0）

- 顶部导航新增“图片管理”，与 Profile 总览、目录与迁移、安全与备份并列。
- 进入页面后先选择一个 Profile；默认可预选当前启用 Profile，但未确认 Profile 前不展示图片。
- 页面始终只展示当前选中 Profile 的图片，禁止跨 Profile 混合展示。
- 图片来源为该 Profile 的受控输出目录、图片索引和任务记录，不读取 Chrome Cookie、Token、密码、验证码或完整认证日志。
- 默认按生成时间倒序，优先展示最近项目；支持时间范围、项目/任务、生成类型、文件格式、尺寸/方向、状态和关键词组合筛选。
- 支持按生成时间、项目最近活动、文件名、文件大小和尺寸排序，以及按项目、任务批次、日期或不分组展示。
- 卡片和详情需显示缩略图、文件名、生成时间、任务/项目、图片类型、尺寸、格式、大小和状态，并支持原图预览、复制路径、打开目录、下载/导出和查看所属任务。
- 必须覆盖加载、空态、无结果、扫描失败、目录不存在、权限错误、文件缺失、文件损坏、生成中和生成失败状态。
- 支持首次扫描、手动重新扫描、生成完成后刷新、目录迁移后重新索引和大图库懒加载。
- 本轮不增加图片删除或批量删除；后续若提出删除，必须单独确认规则和二次确认。
- macOS、Windows、中文目录、空格路径和 Windows 盘符均属于验收范围。

### F22 边界和阶段

- 本轮只更新文档、模块树、开发追踪、测试规划和 UI 壳接入清单，不实现图片管理业务，不修改现有 Profile UI 壳源码。
- 用户先提供图片管理页面的 Stitch Project/Screen、HTML/CSS/资源或其他真实产物；收到后才接入现有控制台，不创建孤立 demo。
- UI 产物接收后必须先完成 Stitch 初次接收检查和实例级细节复修，再进入第一次业务接线目标。
- Codex 负责 macOS 真机、Windows CI 和页面样式检查；用户负责 Windows x64 最终验收。
