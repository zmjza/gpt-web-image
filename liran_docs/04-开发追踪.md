# 开发追踪

> 本表由 [[03-索引]] 的依赖拓扑推导。T01–T38 已完成实现与验证；T39 的 Windows Actions 已在最终提交上通过；T40 macOS 真机已开始但当前受专用 Profile 登录阻塞，T41 保持待用户验收，T42 未执行。
> `已完成` 前必须满足 macOS 真机、Windows CI 和 Windows 用户验收责任，不得跨越门禁。

## 开发顺序

1. 建立项目骨架、Skill 元数据、配置、路径、数据与事件契约。
2. 实现持久化、脱敏、清理、锁与任务编排等不依赖网页的底层能力。
3. 实现浏览器 Profile、首次登录、后台/可视切换。
4. 实现 ChatGPT 网页语义适配、提交幂等和回复绑定。
5. 实现生成状态机、DOM 观察、多信号判定和结构异常升级。
6. 实现图片发现、原图下载、校验、预览和 JSONL 逐张回显。
7. 实现恢复、完整 CLI、Skill 编排与跨平台安装。
8. 完成可控网页夹具、内部全量测试和 Windows CI。
9. 进入第二次 `/goal`：macOS 真机、Windows 用户真机验收、问题回写和版本收口。

## 状态迁移规则

1. `待开发 → 进行中`：第一次 `/goal` 开始对应任务。
2. `进行中 → 内部测试通过`：实现、类型检查、单元/契约/夹具测试有真实证据。
3. Codex 负责部分：`内部测试通过 → 待实测 → 真机测试通过`。
