# GPT 网页生图 Skill 项目说明书

> 项目的源头文档。当前阶段为“T01–T38 内部开发与可控环境验证完成，T39 Windows CI 待实测，T40–T42 未执行”。内部夹具结果不代表真实 ChatGPT 或双平台真机通过。

## 一句话定义

`gpt-web-image` 是一个面向 Codex 用户的跨平台 Skill，通过用户已登录且具备 Plus、Pro 或 Go 会员资格的 ChatGPT 网页生成或修改图片，将原图安全下载到本地，并在当前 Codex 对话中逐张实时回显。

## 解决的问题

用户通过 API 中转站接入 Codex 时无法使用原生生图能力，但已经拥有 ChatGPT Plus 网页端能力。现状要求用户手动切换浏览器、复制提示词、等待、判断状态、逐张下载并重新附回 Codex，步骤多且容易下载错图或丢失任务上下文。

## 目标用户

- 主要用户：当前项目所有者，在 macOS ARM64 与 Windows x64 上使用 Codex。
- 使用场景：文字生图、参考图改图、对已生成结果连续修改、一次请求 1–10 张并在 Codex 中继续处理。
- 账号前提：用户自己拥有并登录 ChatGPT Plus、Pro 或 Go；项目不提供、托管或共享账号。

## 核心价值

1. 在 Codex 对话中用自然语言完成从请求到本地图片交付的完整闭环。
2. 通过任务隔离、多信号监控和文件校验，避免串图、重复提交和误报成功。
3. 每张图片下载成功后立即回显，不等待整批生成结束。

## 项目目标

- 创建用户级 Skill `gpt-web-image`，支持隐式触发与 `$gpt-web-image` 显式触发。
- 首版同时支持 macOS ARM64 与 Windows x64、Google Chrome Stable 和独立持久化 Profile。
- 覆盖文字生图、参考图改图、连续修改、1–10 张数量目标和最多 3 轮补图。
- 以事件驱动状态机监控提交、等待、生成、部分成功、成功、失败、超时、取消和恢复。
- 将每张经校验的原图写入本地，并通过 JSONL `image_ready` 事件驱动 Codex 逐张回显。
- macOS 真机、Windows CI 和 Windows 用户真机验收全部通过后，才进入双平台完成状态。

## 成功标准

- 明确生图请求无需二次确认即可开始；歧义请求在提交前停止并询问。
- 第一次登录可视化，后续正常任务后台运行，必须人工验证时自动切换可视模式。
- 多图任务中第一张合格图片在整批任务完成前显示于当前 Codex 对话。
- 任务只能消费本次绑定回复区域中的新图片，且下载文件可解码、尺寸有效、哈希唯一。
- 中断恢复不得盲目重复提交；无法确定时进入“结果不确定”而非猜测成功。
- 账号凭据不进入仓库、任务记录或诊断日志。

## 边界

- 新增本机 Profile 管理页面和本地管理服务；生图状态文字与图片显示仍使用 Codex 宿主界面。
- 不制作公共插件，不支持多账号并发，不提供云端托管服务。
- 首版不承诺 macOS Intel、Windows ARM64 或 Linux。
- 不调用、逆向或依赖 ChatGPT 私有接口。
- 不绕过验证码、账号限制、内容政策或平台安全机制。
- 不保证网页版 DOM 永久不变；要求在不确定时安全停止并留下脱敏诊断。

## 关键约束

- 技术：跨平台 Node.js、Google Chrome Stable、Playwright 控制能力；依赖选型在实现阶段经失败测试验证后确认。
- 安全：专用 Profile 与输出目录必须位于 Git 之外或被忽略；不得记录敏感认证数据。
- 可靠性：提交动作必须具备幂等保护，下载成功必须通过文件级校验。
- 平台：Windows 不依赖 WSL；路径、锁、进程和文件名必须跨平台处理。
- 验收：Codex 负责 macOS 真机与 Windows CI，用户负责 Windows x64 真机最终验收。

## 本轮新增目标：多 Profile 管理系统

- 在本机管理多个带项目归属标记的 GPT 专用 Chrome Profile，并自动发现默认根目录下的合法 Profile。
- 默认根目录可在 HTML 页面修改；修改时必须让用户选择“迁移”或“保留”。迁移先复制并校验，成功后才切换注册表和移除源目录；保留则历史 Profile 留在原路径，新 Profile 使用新目录。
- 每次只能启用一个 Profile。启用前必须确认 GPT 登录且会员等级明确为 Plus、Pro 或 Go；其他等级、检测技术失败和状态冲突都禁止启用。
- 全局只允许一个项目专用 Chrome 进程；普通浏览可使用其他标签页，生图任务使用独立任务标签页，禁止接管日常 Chrome。
- 页面支持创建、导入、查询、修改、启用、打开/关闭浏览器、检查、删除、完整未加密备份和恢复。
- 页面删除必须二次确认并真实删除指定 Profile；任何自动任务、cleanup、升级或异常恢复都永远不能删除 Profile。
- 备份包含 Chrome 登录数据，只保存在本机并显示敏感数据警告，不进入仓库。
- 本地服务只绑定 `127.0.0.1`，不提供云端、局域网访问或网页账号系统。

## UI 壳流程

本轮适用：管理页面包含列表、表单、弹框、状态切换、迁移预检、备份提示、错误态和响应式布局。文档与微观任务完成后必须进入真实前端 UI 壳四路线；本轮文档阶段不直接创建 UI 壳或接入真实业务。
