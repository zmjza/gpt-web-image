# 首次可视登录

上级：[[_03-浏览器会话]]
下级：无
依赖：[[Profile生命周期]]、[[语义定位与结构兼容]]

---

## 场景

专用 Profile 尚未登录 ChatGPT，必须由账号所有者亲自完成认证。

## 触发

setup 检测不到可用会话，或 Profile 被重置。

## 逻辑

以正式 Google Chrome 打开 ChatGPT；使用项目专用 `user-data-dir` 和预先分配的非零 `127.0.0.1` 调试端口，不使用 Playwright 自动化启动参数。Codex 不输入凭据，只监控登录页、验证页和可用输入区域。检测到稳定的已登录输入区域后记录非敏感就绪标志并正常关闭可视窗口；后续普通任务改用同一 Profile 的 `--start-minimized` 后台窗口。`setup` 输出 `profileDir`、`.gpt-web-image-profile.json` 的 `markerPath` 和 `retentionPolicy=never-auto-delete`，便于确认登录保存在哪个 Profile；关闭 Chrome 不删除该目录，也不影响用户其他 Chrome 窗口。

## 状态 / 边界

验证码、密码、双因素认证只能由用户操作。Google 认证不能使用调试端口 `0`，否则可能被拒绝为“不安全浏览器”。普通 Chrome Profile 的登录不会自动同步到本 Skill Profile；仅页面跳转或访客输入框不算登录成功，必须以可交互输入区域、无登录控件和稳定会话共同确认。
